# Регрессионный набор дистрибутива

Проверки самого набора Gauntlet. В бандл не входят: это тесты для того, кто меняет набор, а не для проекта,
в который набор ставят.

```bash
python3 tests/run.py              # всё, чему достаточно python3, git, bash и JDK 21+ (около двух минут)
python3 tests/run.py --fast       # без самопроверки хуков (самая долгая часть)
python3 tests/run.py --gradle     # плюс сценарии на настоящем Gradle (Gradle 8.14+, Maven Central; несколько минут)
python3 tests/run.py -k crap      # только тесты, в идентификаторе которых есть «crap»
```

Код возврата: 0 — всё зелёное; 1 — есть падение или `-k` не выбрал ни одного теста; 2 — `--gradle` без `gradle`
в `PATH`. Прогон, который ничего не проверил, зелёным не считается.

Набор никогда не проверяет рабочую копию. `run.py` распаковывает `gauntlet-kit-bundle.md` скриптом из шапки
самого бандла, компилирует single-file инструменты и гоняет тесты по этой копии: зелёный прогон относится
к тому, что получит пользователь бандла. Поэтому порядок правки набора такой: изменить файлы в распакованной
копии, пересобрать бандл сборщиком из раздела 8.4 инструкции, запустить `python3 tests/run.py`.

В GitHub Actions набор гоняет `.github/workflows/kit-tests.yml` этого репозитория: на каждый pull request и
push в `main` — `python3 tests/run.py --gradle` на ubuntu-24.04 с Python 3.13, Temurin 21 (по умолчанию) и 25,
Gradle 8.14.3.

Workflow самого набора (`.github/workflows/gauntlet.yml` в бандле) здесь не исполняется: его шаги проверяются
как shell-скрипты, сам workflow — только настоящим прогоном в репозитории, куда набор установлен.
